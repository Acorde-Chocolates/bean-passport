Bean Passport · how a seal is built

Build a seal

This page does in your browser what the factory's Apps Script does inside its spreadsheet: it turns production numbers into the canonical record, its SHA-256 fingerprint, the memo that gets sealed on Solana and the QR code for the wrapper.

Demo: nothing is sent or sealed

0Start from

Load a published batch, then change any number and watch the fingerprint change.

1Production numbers

As the factory's spreadsheet has them: weights in kilograms with a dot for decimals, dates as dates. Leave a step blank if it hasn't happened yet.

2Normalize

The same rules as the Apps Script: kilograms become whole grams, text is trimmed and put in Unicode NFC, dates are yyyy-MM-dd.

    Nothing to rewrite: every value is already in canonical form.

    3Canonical record

    A JSON array of strings in a fixed order, without spaces: the exact bytes that get hashed. The seal of step N covers the header and steps 1 to N.

    —

    4SHA-256 fingerprint

    Computed in your browser from the bytes above. Change one gram and the whole fingerprint changes.

    —

    5Memo

    What the official wallet signs on Solana: version, lot, step and fingerprint.

    —

    Paste it on the sealing page → Apps Script source on GitHub →

    6QR code for the wrapper

    The Apps Script's saveLotQrV1 makes this same SVG, with the same library, and saves it to the factory's Drive. It only carries the passport address, so new seals show up without reprinting.

    Fill in a valid lot code to draw the QR code.

    The factory runs these same steps in Google Apps Script, inside its private spreadsheet. This page only shows them: it can't seal anything.
